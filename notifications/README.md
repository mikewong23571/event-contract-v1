# Event Contract Trading System - Notifications Service

Multi-channel notification service for trading alerts and system messages supporting Telegram, Feishu, Email, and other communication platforms.

## Tech Stack

- **Python**: 3.11+
- **Messaging**: Celery with Redis for async message queuing
- **Telegram**: python-telegram-bot, aiogram for Telegram Bot API
- **Feishu**: larksuiteoapi for Feishu (Lark) integration
- **Email**: aiosmtplib for SMTP email delivery
- **Templates**: Jinja2 for message templating
- **HTTP Clients**: aiohttp, httpx for API integrations
- **Testing**: pytest with async and mocking support

## Installation (uv)

```bash
# Install dependencies (uv)
uv sync

# Include dev extras (tests, linters, etc.)
uv sync --extra dev
```

## Usage

```bash
# Start notification service
notifications

# Start Celery worker for background processing
uv run celery -A src.main:celery_app worker --loglevel=info

# Send test notification via CLI
notify --channel telegram --message "Test alert" --priority high

# Send trading signal notification
notify --template trading_signal --data '{"symbol":"BTCUSDT","direction":"UP","probability":0.75}'
```

## Repo Workflow (uv + Make)

- 推荐使用仓库根目录的 Make 命令统一操作：
  - `make dev` 启动基础设施与所有应用服务（通过 uvx honcho + Procfile.dev）
  - `make test` 统一运行测试
  - `make format` / `make lint` / `make type-check` 执行代码质量工具
  - 所有 Python 工具均通过 `uv run` 运行，无需全局安装

## Features

- **Multi-Channel Support**: Telegram, Feishu, Email, and extensible for other platforms
- **Template Engine**: Jinja2 templates for consistent message formatting
- **Async Processing**: Celery-based background processing with Redis
- **Rate Limiting**: Configurable rate limiting to respect API limits
- **Retry Logic**: Automatic retry with exponential backoff for failed notifications
- **Message Queuing**: Redis-based message queuing for reliable delivery
- **Monitoring**: Prometheus metrics and health checks
- **Internationalization**: Multi-language template support

## Configuration

Configure via environment variables or `.env` file:

```bash
# Redis/Celery
REDIS_URL=redis://localhost:6379/1
CELERY_BROKER_URL=redis://localhost:6379/1

# Telegram Bot
TELEGRAM_BOT_TOKEN=your_bot_token
TELEGRAM_CHAT_IDS=chat1,chat2,chat3
TELEGRAM_ENABLED=true

# Feishu (Lark)
FEISHU_APP_ID=your_app_id
FEISHU_APP_SECRET=your_app_secret
FEISHU_WEBHOOK_URL=https://open.feishu.cn/...
FEISHU_ENABLED=true

# Email (SMTP)
SMTP_HOST=smtp.gmail.com
SMTP_PORT=587
SMTP_USERNAME=your_email@gmail.com
SMTP_PASSWORD=your_password
SMTP_FROM_EMAIL=alerts@yourdomain.com
EMAIL_RECIPIENTS=trader1@email.com,trader2@email.com
EMAIL_ENABLED=true

# Notification settings
MAX_RETRY_ATTEMPTS=3
RETRY_DELAY=5.0
BATCH_SIZE=100
RATE_LIMIT_PER_MINUTE=60

# Templates and localization
TEMPLATE_DIR=templates
DEFAULT_LANGUAGE=en
```

## API Integration

### Telegram Bot
- Creates and manages Telegram bot instances
- Supports group chats and direct messages
- Handles inline keyboards for interactive notifications
- Respects Telegram API rate limits (30 messages/second)

### Feishu (Lark)
- Webhook-based message delivery
- Rich message formatting with cards and buttons
- Group chat and direct message support
- Enterprise features for team notifications

### Email
- HTML and text templates
- Attachment support for reports
- SMTP authentication and TLS encryption
- Bulk email handling with proper headers

## Monitoring

- **Message Delivery**: Success/failure rates per channel
- **Queue Health**: Redis queue size and processing time
- **Rate Limiting**: API call rates and throttling metrics
- **Error Tracking**: Failed deliveries with retry attempts
- **Performance**: Message processing latency

## Error Handling

- **Exponential Backoff**: Retry failed deliveries with increasing delays
- **Dead Letter Queue**: Store permanently failed messages
- **Circuit Breaker**: Temporarily disable failing channels
- **Fallback Channels**: Route messages to alternative channels on failure
