# App UI 一致性与交互规范（v0.1）

本文档将前一轮审查与设计产出“持久化”，用于指导前端页面的统一交互与呈现，实现跨页面的一致性、复用性与对齐。

## 一、原始问题（来自用户的诉求）
- “回测界面的按钮和输入框” —— 需要了解回测页的输入与按钮现状，并提出改进建议。
- “问题我帮你用红色的线圈出来了，修复这个排版布局问题” —— 针对 Backtesting 页标题与表单、按钮左右分散的布局错位，要求修复。
- “先查看 app 目录下的所有组件，看看他们都需要展示哪些输入框，按钮，提示元素。你需要考虑一个最好的交互和呈现方案，保证组件的一致性，重复性，对齐。” —— 需要通盘盘点并制定统一方案。

## 二、目标
- 建立统一的页面结构与交互规范，减少样式与结构分歧。
- 通过复用组件降低重复代码与维护成本。
- 在各断点下保证对齐、可读性与可用性。

## 三、适用范围
- 前端目录：`frontend/src/app/` 下的各页面。
- 当前重点页面：Backtesting、Market Data、Signals、Alerts、Risk、Home/Dashboard。

## 四、现状盘点摘要（按页面）
- Backtesting：多输入框（策略、交易对、起止日期），主要按钮（Create/Refresh），存在中大屏标题与表单、按钮分散的问题（已修复为竖向流）。
- Market Data：有 Input、原生 select、Refresh 按钮；布局不完全一致。
- Signals：有 Input、生成/刷新按钮，错误提示；头部布局与其它页面存在差异。
- Alerts：Reconnect、Clear 按钮，连接状态与空态提示；头部采用左右分布。
- Risk：若干输入、select 与保存按钮；网格/弹性布局混用。
- Home：主要是入口按钮，无表单元素。

## 五、统一交互与呈现方案
1) 标准页面头 PageHeader
- 组成：标题（必填）+ 副标题（可选）+ 右侧操作区（可选）。
- 对齐：标题与副标题左对齐，操作区与内容保持等距与对齐。
- 响应式：小屏换行为上下两行；大屏同一行内左标题右操作。

2) 控制条 ControlBar（筛选/动作区）
- 组成：表单元素（Input/Select/Date）+ 主按钮（主操作）+ 次按钮（刷新/重置）。
- 排列：小屏纵向堆叠；≥sm 水平流动，允许换行；末尾按钮区对齐在一行末端或紧随表单最后一列。
- 间距：控件间 gap-x-3/gap-y-2；区块与列表/表格之间间距 16–24px。

3) 表单栅格 FormGrid
- 列宽：小屏 1 列；≥sm 2 列；≥lg 3 列（可按页面复杂度调整）。
- 标签与控件：同一行左标签右控件，或上标签下控件，保持全站一致。
- 校验：必填星号统一位置与颜色；错误提示同一行/下一行一致样式。

4) 反馈组件
- ErrorBanner：顶部显式错误，红色弱背景 + 可关闭。
- SuccessNote：成功提示，绿色弱背景 + 自动淡出或可关闭。
- StatusIndicator：用于连接/运行状态的小型点状指示与文案。

5) 元素规范
- Button：主按钮使用强调色（实心），次按钮幽灵/描边；禁用态统一不透明度与禁用光标。
- Input/Select：统一高度、圆角、内边距；原生 select 逐步替换为统一的 UI Select。
- 日期：使用一致的日期选择器与格式（YYYY/MM/DD），区间选择提供最小/最大限制与互相校验。

6) 响应式与对齐
- 断点：sm、md、lg 基于 Tailwind 默认；小屏免左右分散，避免“标题在左、按钮在右”的错位。
- 对齐：左侧对齐线统一；按钮随表单末列自然排布或在小屏位于表单下方。

7) 状态与可用性
- 加载：主操作中显示 loading 状态并禁用其它相关控件。
- 空态：统一空态插画/文案风格（轻量）+ 引导操作。
- 错误：统一字段校验与顶部错误提示的组合策略。

8) 文案与可访问性
- 文案：动词开头，简洁一致；中英文或仅中文，保持统一风格。
- A11y：控件需有可读 label/aria-*；颜色对比度满足可读性。

## 六、复用组件清单（草案 API）
- PageHeader
  - props：title、subtitle、actions（ReactNode）
- ControlBar
  - props：children（放置表单控件与按钮，内部负责响应式间距与对齐）
- FormGrid
  - props：colsSm=1、colsMd=2、colsLg=3、children
- ErrorBanner
  - props：message、onClose
- SuccessNote
  - props：message、durationMs?
- StatusIndicator
  - props：status=(success|warning|error|idle|loading)、text

## 七、实施步骤与里程碑
- M1：落地复用组件于 `components/ui`，完成样式基线与 Story/示例。
- M2：Backtesting 首个试点替换（含 select 统一），验证响应式与校验流。
- M3：Market Data、Signals、Alerts、Risk 逐页替换与统一。
- M4：全局自检（桌面/移动、对齐、换行、禁用/加载/错误/成功一致性）。
- M5：规范沉淀与后续维护指引。

## 八、验收清单（抽样核对）
- 标题与副标题左对齐、操作区不与标题“隔空对齐”。
- 小屏纵向、≥sm 水平流，按钮不跑到标题对侧造成割裂。
- Input/Select/Date 尺寸、圆角、间距一致；select 风格统一。
- 错误与成功提示的样式与出现位置一致。
- 主操作在加载时禁用并有进度/状态体现。

## 九、已实施修复（记录）
- Backtesting：移除中/大屏的左右分栏，改为统一纵向流，标题与表单/按钮在同一视觉流内，避免错位与分散。

—— 以上为 v0.1 提案，后续可根据页面落地反馈做微调。
